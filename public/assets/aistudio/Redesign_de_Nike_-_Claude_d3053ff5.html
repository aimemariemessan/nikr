Cette demande modifie deux choses que j’avais écrites, donc le bloc précédent est à remplacer.

Ce qui change par rapport au bloc précédent

  1. Le hero devient un hero image. J’avais choisi « typographique pur » faute de vraies photos. Avec une barre transparente sur une image qui prend toute la place, il te faut une vraie photo dès le départ, sinon l’effet ne marche pas. Dans le kit, c’est l’archétype n°2 (« image unique plein cadre »).
  2. Le hero commence maintenant à top: 0, sous la barre. Le calcul 100svh - var(--header-h) du bloc précédent est faux dans ce cas, il faut simplement 100svh.

Mon avis sur « fond blanc plein ou backdrop »

  • Fond plein : à choisir par défaut. Il est plus net visuellement pour un style magazine, et plus fiable à lire quand le contenu défile dessous.
  • Backdrop (flou) : c’est faisable, mais le texte devient moins lisible quand une image claire passe dessous, et le kit surveille déjà le glassmorphism. Je le garde comme variante.
  • Le blanc pur (#FFFFFF) n’est pas dans ta palette (le fond est #D9D9D4, un gris béton). Une barre blanche sur une page grise ressemble à une autre matière. J’utilise donc la couleur bg de la palette, et je passe la couleur dans une variable pour que tu puisses mettre du blanc en changeant une seule ligne.

Pièges techniques que j’ai intégrés dans le prompt

  • Pages sans hero (liste produits, fiche produit, panier) : une barre transparente avec texte blanc y serait invisible sur le fond clair. Elle doit être pleine dès le chargement sur ces pages. C’est l’oubli le plus fréquent avec ce type de barre.
  • Menu mobile ouvert : la barre doit aussi passer en plein, sinon le menu flotte sur l’image.
  • Lisibilité sur image : tu ne contrôles pas la photo, donc un voile sombre discret en haut et en bas est nécessaire pour garder le texte lisible (contraste AA). C’est un voile fonctionnel, pas un dégradé décoratif.
  • Contraste du bouton orange : j’ai calculé du texte blanc sur #FF3B1F à environ 3,6:1, ce qui échoue pour du texte normal. Du texte noir #101010 donne environ 5,3:1. Le bouton CTA a donc un texte noir.
  • Image du hero : elle ne doit pas être en chargement différé (lazy), contrairement à mes consignes générales sur les images. C’est l’élément principal de la page.

Bloc à remplacer dans le prompt (lignes « HEADER » et « HERO »)

HEADER : position fixed en haut (top-0 inset-x-0 z-50), deux états.

ÉTAT 1 — sur le hero, au chargement : fond transparent, logo/liens/icônes en blanc (utiliser currentColor pour que les icônes changent avec le texte). Aucun bouton en pilule dans la barre.
ÉTAT 2 — après défilement : fond plein couleur « bg » de la palette via la variable --header-solid-bg (valeur par défaut #D9D9D4, modifiable), texte et icônes en couleur « text » (#101010), filet inférieur de 1px. Variante alternative activable via data-header-style="blur" : fond bg à 80 % d'opacité + backdrop-blur-md.

DÉCLENCHEMENT : utilise un IntersectionObserver (pas un écouteur scroll) sur un élément sentinelle placé tout en haut du hero ; quand il sort de la vue, la barre passe à l'état 2 (classe is-solid), et revient à l'état 1 au retour en haut.
TRANSITION : 250 ms ease sur background-color, color et border-color uniquement (jamais transition-all). Désactivée si prefers-reduced-motion.

RÈGLES ANNEXES
- Sur toutes les pages SANS hero (products.html, product.html, panier) : la barre est à l'état 2 dès le chargement (attribut data-header="solid" sur le body).
- Menu mobile ouvert : la barre passe à l'état 2 tant qu'il est ouvert.
- Tiroir panier ouvert : la barre reste sous l'overlay.

HERO : plein écran, l'image prend toute la place, SOUS la barre transparente.
- <section> en min-h-screen (repli) puis min-h-[100svh], qui commence à top 0 (pas de calcul avec la hauteur du header). N'utilise JAMAIS h-screen ni 100vh seul.
- Image : <img> en position absolute, inset-0, w-full h-full object-cover, object-position réglable via variable --hero-pos. Fichier local /img/hero.webp, avec srcset 768w / 1280w / 1920w, width et height définis, fetchpriority="high", loading="eager" (surtout PAS lazy), decoding="async". Alt vide si l'image est décorative, descriptif sinon.
- Repli si l'image manque : fond couleur « surface », aucune cassure de mise en page.
- Lisibilité : deux voiles fonctionnels au-dessus de l'image — un dégradé noir de 0 à 50 % d'opacité sur les 160 premiers pixels (pour la barre) et un autre de 0 à 55 % sur le tiers inférieur (pour le titre). Texte du hero en blanc. Vérifie un contraste AA (4.5:1) du texte de la barre sur la partie la plus claire de l'image.
- Contenu en flex flex-col justify-between : en haut sous la barre, une ligne méta en JetBrains Mono (ex. « Collection automne 2026 — 12 références ») ; en bas, titre + CTA alignés à gauche. Padding bas : env(safe-area-inset-bottom).

- CTA : un seul bouton « Voir les nouveautés », fond accent-1 (#FF3B1F), TEXTE NOIR #101010 (le blanc ne passe pas le contraste), qui fait défiler vers la grille produits.

## 1. CONTRAINTES TECHNIQUES (non négociables)
- HTML5 + Tailwind CSS via CDN (<script src="https://cdn.tailwindcss.com"></script>) + JavaScript vanilla.
- AUCUN framework ni build step : pas de React, Vue, Next.js, Svelte, Vite. Le projet s'ouvre en double-cliquant sur index.html.
- Pas de backend. Produits dans js/products-data.js (tableau d'objets), panier dans localStorage. Devise : une constante CURRENCY en haut de js/cart.js, formatage avec Intl.NumberFormat.
- Fichiers :
  index.html, products.html, product.html (chargée via ?id=)
  js/products-data.js, js/cart.js, js/filters.js, js/main.js, js/layout.js (header, footer et tiroir panier injectés depuis un seul endroit, jamais dupliqués)
  css/custom.css (uniquement ce que Tailwind ne couvre pas : variables, polices, animations)
  img/ (hero-768.webp, hero-1280.webp, hero-1920.webp) et img/products/
- Polices : Google Fonts uniquement.
- Juste après le script CDN, configure Tailwind ainsi :
  tailwind.config = { theme: { extend: { colors: { bg:'#D9D9D4', surface:'#C7C7C0', ink:'#101010', muted:'#55564F', alert:'#FF3B1F', signal:'#0033A0' }, fontFamily: { display:['"Big Shoulders Display"','Impact','sans-serif'], sans:['"Hanken Grotesk"','system-ui','sans-serif'], mono:['"JetBrains Mono"','ui-monospace','monospace'] } } } }
